# Deliberate LFS/BLFS deviations

1. **Container target:** no partition, filesystem formatting, kernel image, initramfs, GRUB, EFI or ISO. Skip LFS chapter 8 GRUB and chapter 10 boot procedures. Build Linux API headers normally. Empty `/boot` is harmless.
2. Workspace directories replace a dedicated partition. `$LFS/tools` is a bind mount; `/sources` is a physical directory (see item 16); recipes see the book's original paths. A dedicated `logos-lfs` account replaces the generic `lfs` name to avoid adopting an existing account. Noninteractive `env -i` replaces login dotfiles without changing compiler flags.
3. Chapter 8 systemd stays in book order. Stage 04 configures it; it does not move systemd ahead of its dependencies.
4. Set UTC, A4 paper, en_US.UTF-8. Lock root/LogOS passwords; use LXD exec for administration. Omit interactive `tzselect`, `passwd root`, Vim option browser and replacement interactive Bash process. Select fresh glibc installation, not upgrade-only paths; install book test locales rather than all locales. See `lfs-command-adaptations.txt` for exact extracted-block omissions.
5. Keep tests strict. A diagnostic grep for failing binutils tests succeeds only when it finds no failures. Omit optional root util-linux tests; run the prescribed tester-user suite. Book tests with known environmental failures still stop for diagnosis; no blanket success override.
6. Use systemd-networkd DHCP on `eth0`, resolved and a stub resolver link. Empty machine-id at image creation, volatile bounded journal. Mask only host-controlled time synchronization, kernel module loading and physical tty1 getty. Other failed units are **not** automatically accepted. There are no verified degraded-state exceptions yet.
7. Select only Xorg protocol/client libraries needed for xterm, plus xdpyinfo. Use core X fonts provided by the host Xephyr; omit optional FreeType and desktop libraries. Xterm and tmux are built from source. tmux uses its upstream release because it is not covered by this BLFS book.
8. BLFS optional documentation requiring extra toolchains is omitted for libuv and libevent. Build make-ca/p11-kit trust stores from pinned Mozilla NSS certdata instead of a floating online update; no custom CA examples, update timer, or host CA bundle copying.
9. NVIDIA CUDA is proprietary userspace, installed from checksummed NVIDIA 12.9.1 redistributables (NVCC, CUDA runtime, CCCL, cuBLAS). No runfile driver, host driver installation, or CUDA 13. Build a separate GNU GCC 14.3.0 in `/opt/gcc-14` for NVCC compatibility; retain the book's system compiler/runtime. This compatibility compiler is outside BLFS 13.1 and uses upstream source/SHA512.
10. Pin llama.cpp to the commit in `sources/ai.json`, build with `GGML_CUDA=ON`, architecture 52, native CPU tuning disabled for portability, CUDA graphs off on Maxwell, HTTPS, subprocess tooling, unified app and server web UI disabled with the pinned upstream CMake options. Check actual CUDA computation through LXD before building llama.cpp. No CPU-only completion mode.
11. NVIDIA driver userspace integration is provided only through LXD CDI or its NVIDIA runtime. Ubuntu libc, Bash, Python, systemd, coreutils and X libraries are never copied into LogOS. Image ABI validation runs `ldd` inside chroot and rejects unresolved, temporary-toolchain and Ubuntu multiarch paths.
12. Source download and recipe execution are logged and fingerprinted. Packaging excludes source/build files rather than removing the diagnostic build tree. Preserve license files bundled with NVIDIA components. Install LogOS identity and software in the final stage.

These adaptations have not yet been validated by a full rootfs build; see `validation.md`. Any new compatibility patch must be recorded here after diagnosing an actual failure.

13. xdpyinfo also requires libXtst; include libXfixes, libXi and libXtst after inspecting its actual configure.ac. The host-version checker returns a nonzero exit status for every failed book prerequisite and uses an isolated scratch directory.

14. Preserve GCC/glibc compiler-support static archives; omit optional full-system stripping and remove only unnecessary binutils archives/libtool metadata. Export the book's `set +h` and umask 022 in generated recipe preambles. The image can retain development tools without breaking their support libraries.

15. MPC and Patch use the canonical HTTPS GNU archive with the unchanged book MD5. The GNU redirector returned HTTP 404 for MPC and an expired-mirror TLS certificate for Patch during the actual download. TLS verification stays enabled. The original wget-list is retained verbatim.
16. Actual build diagnosis: the cross-built temporary Bash uses its fallback `getcwd`, which fails across a bind mount of a different directory on the same filesystem. This caused 13 glibc test failures and shell-init diagnostics. Keep the physical work tree at `$LFS/sources` as in LFS, with `$LOGOS_BUILD/work` as a convenience symlink; keep the verified download cache at `$LOGOS_BUILD/sources`. No Bash/compiler flags were changed. A before/after chroot probe and glibc retest confirmed the fix.
17. The remaining glibc `io/tst-lchmod` failure is the LFS 13.1 documented chroot exception: descriptor 1 changes from a chroot-relative path to its host path when the test leaves the chroot. The verifier accepts only that specific diagnostic, a fresh complete summary and over 6000 passing tests. All other failures remain fatal. Preserve test summaries and failure output under `logs/tests`.
18. `--accept-input-changes` supports an explicitly reviewed build-runner repair. It audits against the previous input snapshot and all completed package markers; changes to completed recipes, source locks, package ordering, completed stage scripts or installed overlays are rejected. Incomplete recipes can be repaired and retried without rebuilding successful packages. Repairs are recorded in history.tsv.
19. Actual final Binutils tests produced only the LFS-documented gprofng failure: `tmpdir/gp-gmon`, with `No calltree` in gprofng.log. All assembler/linker/other Binutils tests completed without unexpected failures. Retain gprofng and run every suite; accept only this diagnosed case with fresh complete summaries for all six suites. Other FAIL/XPASS/ERROR results stop the build.
20. Corrected extraction of the GMP recipe: omit the illustrative `ABI=32 ./configure ...` command from the conditional 32-bit x86 note. The actual x86_64 configure command and the book's GCC 15+ compatibility sed remain unchanged. Added this placeholder to the recipe validation check.
21. The development disk is mounted `nosuid,nodev`. ACL's real device-permission test failed on `nodev`; a private self-bind of the rootfs with `dev,suid` made it pass. Apply those flags only within the build's private mount namespace; the host disk mount remains `nosuid,nodev`. This also restores normal LFS setuid test semantics. Chown the physical `/sources` directory at the chroot handover rather than its convenience symlink.
22. ACL's remaining `test/cp` failure is documented by LFS 13.1 because temporary Coreutils has no ACL preservation support yet. Accept only the observed two cp-preservation mismatches with 13 PASS, 2 XFAIL and no other failures. Final Coreutils is still built in normal book order with ACL support.
23. Python's full test suite exposed missing DNS in the build chroot (`test_urllib2` and `test_urllibnet`). The chroot shares the host network; provide the host resolver configuration only in its private volatile `/run/systemd/resolve/stub-resolv.conf`, reached through the same resolver symlink used by the finished container. No host resolver configuration is packaged. Keep Python's full test command unchanged.
24. Separate CUDA userspace preparation from actual GPU verification within stage 08. A fingerprinted preparation checkpoint preserves the toolkit/compiler/diagnostic across a host driver repair; stage 08 still cannot complete until the LXD CUDA kernel test succeeds. Inspect nvidia-smi before preparation and fail at GPU verification if it remains unavailable. Run the compatibility compiler tests as the existing unprivileged tester account, matching the LFS compiler test environment.
25. Findutils 4.11.0 produced the LFS-documented `test-regex-el` failure: exactly three Greek-locale regex fastmap mismatches. Check fresh complete results from all six Automake/DejaGNU suites and accept only that diagnostic; any other failure remains fatal. Preserve the exception as a failed upstream test rather than reporting it passed.
