# Deliberate LFS/BLFS deviations

1. **Container target:** no partition, filesystem formatting, kernel image, initramfs, GRUB, EFI or ISO. Skip LFS chapter 8 GRUB and chapter 10 boot procedures. Build Linux API headers normally. Empty `/boot` is harmless.
2. Workspace directories replace a dedicated partition. `$LFS/tools` and `/sources` are bind mounts; recipes see the book's original paths. A dedicated `logos-lfs` account replaces the generic `lfs` name to avoid adopting an existing account. Noninteractive `env -i` replaces login dotfiles without changing compiler flags.
3. Chapter 8 systemd stays in book order. Stage 04 configures it; it does not move systemd ahead of its dependencies.
4. Set UTC, A4 paper, en_US.UTF-8. Lock root/LogOS passwords; use LXD exec for administration. Omit interactive `tzselect`, `passwd root`, Vim option browser and replacement interactive Bash process. Select fresh glibc installation, not upgrade-only paths; install book test locales rather than all locales. See `lfs-command-adaptations.txt` for exact extracted-block omissions.
5. Keep tests strict. A diagnostic grep for failing binutils tests succeeds only when it finds no failures. Omit optional root util-linux tests; run the prescribed tester-user suite. Book tests with known environmental failures still stop for diagnosis; no blanket success override.
6. Use systemd-networkd DHCP on `eth0`, resolved and a stub resolver link. Empty machine-id at image creation, volatile bounded journal. Mask only host-controlled time synchronization, kernel module loading and physical tty1 getty. Other failed units are **not** automatically accepted. There are no verified degraded-state exceptions yet.
7. Select only Xorg protocol/client libraries needed for xterm, plus xdpyinfo. Use core X fonts provided by the host Xephyr; omit optional FreeType and desktop libraries. Xterm and tmux are built from source. tmux uses its upstream release because it is not covered by this BLFS book.
8. BLFS optional documentation requiring extra toolchains is omitted for libuv and libevent. Build make-ca/p11-kit trust stores from pinned Mozilla NSS certdata instead of a floating online update; no custom CA examples, update timer, or host CA bundle copying.
9. NVIDIA CUDA is proprietary userspace, installed from checksummed NVIDIA 12.9.1 redistributables (NVCC, CUDA runtime, CCCL, cuBLAS). No runfile driver, host driver installation, or CUDA 13. Build a separate GNU GCC 14.3.0 in `/opt/gcc-14` for NVCC compatibility; retain the book's system compiler/runtime. This compatibility compiler is outside BLFS 13.1 and uses upstream source/SHA512.
10. Pin llama.cpp to the commit in `sources/ai.json`, build with `GGML_CUDA=ON`, architecture 52, native CPU tuning disabled for portability, CUDA graphs off on Maxwell, HTTPS, subprocess tooling, unified app and server web UI disabled with the pinned upstream CMake options. Check actual CUDA computation through LXD before building llama.cpp. No CPU-only completion mode.
11. NVIDIA driver userspace integration is provided only through LXD CDI or its NVIDIA runtime. Ubuntu libc, Bash, Python, systemd, coreutils and X libraries are never copied into LogOS. Image ABI validation runs `ldd` inside chroot and rejects unresolved, temporary-toolchain and Ubuntu multiarch paths.
12. Source download and recipe execution are logged and fingerprinted. Packaging excludes source/build files rather than removing the diagnostic build tree. Preserve license files bundled with NVIDIA components. Install LogOS identity and software in the final stage.

These adaptations have not yet been validated by a full rootfs build; see `validation.md`. Any new compatibility patch must be recorded here after diagnosing an actual failure.

13. xdpyinfo also requires libXtst; include libXfixes, libXi and libXtst after inspecting its actual configure.ac. The host-version checker returns a nonzero exit status for every failed book prerequisite and uses an isolated scratch directory.

14. Preserve GCC/glibc compiler-support static archives; omit optional full-system stripping and remove only unnecessary binutils archives/libtool metadata. Export the book's `set +h` and umask 022 in generated recipe preambles. The image can retain development tools without breaking their support libraries.

15. MPC and Patch use the canonical HTTPS GNU archive with the unchanged book MD5. The GNU redirector returned HTTP 404 for MPC and an expired-mirror TLS certificate for Patch during the actual download. TLS verification stays enabled. The original wget-list is retained verbatim.
